# Blik

Система заявок на техническое обслуживание для колледжа.

Заявитель (сотрудник/преподаватель) указывает кабинет и описывает проблему; системные администраторы
(с тремя уровнями доступа — главный сисадмин, сисадмин, практикант) берут заявку в работу, классифицируют
её (категория/приоритет), ведут переписку с заявителем и закрывают заявку. Вход — через Active Directory
(LDAP), плюс локальный breakglass-аккаунт на случай недоступности AD.

Подробный план архитектуры и этапов реализации: см. историю обсуждения в чате/плане проекта.

## Структура репозитория

```
apps/
  backend/   — NestJS API (auth, tickets, sla, notifications, ...)
  frontend/  — React (Vite) SPA
infra/
  docker-compose.yml — postgres + backend + frontend + nginx
```

## Быстрый старт (разработка)

```bash
npm install                       # установит зависимости во всех workspaces
cp infra/.env.example infra/.env  # заполнить переменные окружения (LDAP, JWT, master-аккаунт)

npm run prisma:migrate            # применить миграции БД (нужен запущенный Postgres)
npm run build:backend             # prisma db seed запускает скомпилированный dist/prisma/seed.js
npm run prisma:seed               # создать master-аккаунт из env

npm run dev:backend               # http://localhost:3000 (Swagger: /api/docs)
npm run dev:frontend              # http://localhost:5173
```

Полный стек через Docker:

```bash
docker compose -f infra/docker-compose.yml up --build
```

## Панель локальных сервисов

Раздел **Сервисы** (`/services`) доступен только сисадминам (`ADMIN`), в том числе
через нижнюю панель на телефоне. Преподаватели и практиканты не видят раздел и не
имеют доступа к его API.

Кнопка **Добавить сервис** открывает настройки названия, HTTP(S)-ссылки (включая
локальные IP-адреса и имена хостов), описания, эмодзи или собственной картинки.
Поддерживаются PNG, JPEG, WebP и GIF до 512 КБ. Значение «Порядок в панели» задаёт
сортировку: меньшие числа идут первыми. Меню **⋯** на плитке объединяет изменение,
копирование ссылки, скрытие и удаление. Фильтр **Все сервисы** показывает скрытые
плитки, чтобы их можно было вернуть в панель. Поиск учитывает название, описание и ссылку.

Настройки и картинки хранятся в таблице `LocalService`. При обновлении через
Portainer пересоберите **backend и nginx**: миграция создаст таблицу автоматически
при запуске backend (`prisma migrate deploy`). Для запуска вне Docker примените
миграции командой `npm run prisma:deploy --workspace apps/backend`.

## Уведомления и вход через MAX

1. Задайте `MAX_BOT_TOKEN` в окружении сервера (в Portainer: Stack → Environment variables,
   при Docker Compose: `infra/.env`). Это токен того же бота, из которого открывается приложение.
   Пересоберите и перезапустите backend и nginx после обновления кода.
2. В настройках бота подключите мини-приложение с HTTPS-адресом `https://<ваш-домен>`.
   Подписанный запуск MAX автоматически включает вход и привязку на главной странице,
   даже при наличии старой сессии Blik. Адрес `/max` также поддерживается.
3. Пользователь запускает бота и открывает мини-приложение внутри MAX, затем один раз
   вводит логин и пароль Blik. Аккаунт привязывается автоматически. Обычная форма входа,
   открытая внутри MAX, также привязывает аккаунт. При повторном открытии `/max` вход
   выполняется без пароля. Внешний браузер не передаёт подписанные данные MAX и сам
   по себе привязать аккаунт не может.
4. После привязки уведомления отправляются в личный диалог пользователя с ботом через
   `POST https://platform-api2.max.ru/messages?user_id=...`. Webhook для этого не нужен.
   Личные настройки уведомлений и тихие часы продолжают действовать. Статус привязки
   и отвязка доступны в настройках MAX; результат доставки записывается в `NotificationDelivery`.

Для проверки отправьте пользователю тестовое уведомление через существующую рассылку
администратора (с другого аккаунта): оно должно появиться в Blik и в чате бота.
Ошибки API записываются как `FAILED` с HTTP-кодом, сетевые ошибки — отдельно.
Автоматического повтора неуспешных отправок нет.

По [документации MAX](https://dev.max.ru/docs-api) для API может потребоваться доверенный
сертификат Минцифры. Если сервер сообщает об ошибке TLS, установите официальный CA в PEM
и передайте Node.js путь через `NODE_EXTRA_CA_CERTS` (в контейнере файл нужно также
смонтировать). Не отключайте проверку TLS.

## Расписание колледжа

Расписание для групп, преподавателей и кабинетов открывается без входа по адресу
[blik.tgiek.ru/schedule](https://blik.tgiek.ru/schedule). Blik читает основное
расписание и замены из публичных Google-таблиц проекта `blik-schedule`.
При необходимости их ID задаются через `SCHEDULE_MAIN_SHEET_ID` и
`SCHEDULE_CHANGES_SHEET_ID`.

В разделе **Пользователи** сисадмин назначает редактору роль **Расписание**.
После входа редактор сразу попадает на `/manage-schedule`. Там можно задать цвет
текущей недели, изменить пару по группе и дню недели и опубликовать объявление.
Карточка **Рассылка в MAX** отправляет разовое сообщение подписчикам объявлений.
Кнопки **Мои заявки** и **Новая заявка** открывают работу с заявками Blik с правами преподавателя.
Цвет чередуется автоматически по понедельникам. Правки пар хранятся в Blik.
Кнопка **Вернуть из таблицы** снимает правку. Опубликованные замены на конкретную
дату показываются поверх обычного расписания.

Для отдельного бота расписания в Portainer задайте `SCHEDULE_MAX_BOT_TOKEN` и
`SCHEDULE_MAX_WEBHOOK_SECRET` в переменных стека. Секрет можно сгенерировать
командой `node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"`.
После пересборки backend и nginx зарегистрируйте webhook из консоли контейнера
backend:

```sh
node dist/college-schedule/register-bot.js
```

В настройках мини-приложения отдельного бота укажите
`https://blik.tgiek.ru/schedule`. Для подписки пользователь запускает диалог с ботом кнопкой **Начать**
и открывает расписание в MAX. В разделе **Уведомления MAX** можно выбрать замены для одной группы
или преподавателя и отдельно включить объявления колледжа. Та же кнопка на публичном сайте открывает
мини-приложение для подтверждения аккаунта MAX. Бот отправляет новые и исправленные замены из
таблицы, правки пар из Blik и новые объявления. Уже опубликованное содержимое не рассылается при обновлении стека.
[Документация MAX по вебхукам](https://dev.max.ru/docs-api/methods/POST/subscriptions).
